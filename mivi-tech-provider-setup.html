Como funciona o modelo multitenant

A MIVI é a Tech Provider — dona do app Meta. Os clientes da MIVI são empresas que conectam suas WABAs ao app da MIVI via Embedded Signup. Cada cliente tem sua própria WABA, número e credenciais — mas tudo passa pelo mesmo app e webhook.

Etapa 1 — Uma vez

Conta Meta Developer + Business Manager da MIVI

Toda a estrutura central da MIVI precisa estar configurada antes de qualquer cliente conectar. Estes passos são feitos uma única vez.

Conta Meta Developer Uma vez
  1. Acesse developers.facebook.com e crie a conta com uma conta Facebook vinculada ao domínio corporativo da MIVI. Confirme número de telefone quando solicitado.
  2. Aceite os Termos de Desenvolvedor. A conta deve ter pelo menos alguns meses de existência — contas recém-criadas aumentam o risco de rejeição no App Review.
Business Manager da MIVI Uma vez
  1. Acesse business.facebook.com e crie o Business Manager em nome da MIVI com o nome legal exato da empresa.
  2. Em Configurações do negócio → Informações do negócio, preencha endereço, telefone e site corporativo.
  3. Guarde o ID do Business Manager — ele será necessário durante o cadastro do app e durante o processo de Tech Provider.
    Onde encontrar
    Configurações do negócio → Informações do negócio → ID do negócio
Etapa 2 — Uma vez

Criar e configurar o App Meta da MIVI

Este é o app central. Todos os clientes da MIVI conectam suas WABAs aqui via Embedded Signup. O webhook é configurado aqui uma única vez e recebe eventos de todos os tenants.

Criar o app Uma vez
  1. Acesse developers.facebook.com/apps e clique em Criar app.
  2. Selecione o tipo Business. Clique em Avançar.
  3. Nome do app: use um nome interno claro, sem mencionar "WhatsApp", "Meta" ou qualquer produto da Meta — a Meta rejeita apps com esses termos no nome. Ex: MIVI Platform ou MIVI Messaging.
  4. Vincule ao Business Manager da MIVI criado na etapa anterior. Clique em Criar app.
  5. No app criado, vá em Configurações → Básico e preencha:
    — URL da política de privacidade da MIVI
    — URL dos termos de serviço
    — Ícone (mínimo 1024×1024px)
    — Categoria: Business and Pages
  6. Clique em Salvar alterações. Guarde o App ID e o App Secret — serão usados no Embedded Signup e nas chamadas de API.
⚠️
O app começa em modo de desenvolvimento. Em modo dev, só usuários adicionados como testadores conseguem passar pelo Embedded Signup. A passagem para modo Live acontece após o App Review ser aprovado.
Adicionar o produto WhatsApp ao app Uma vez
  1. No painel do app, clique em Adicionar produto (no menu lateral).
  2. Encontre WhatsApp e clique em Configurar.
  3. Selecione o Business Manager da MIVI para vincular. O WhatsApp Business aparecerá no menu lateral do app.
Configurar o Webhook Uma vez
  1. No menu lateral do app, vá em WhatsApp → Configuração → Webhooks.
  2. Clique em Configurar webhooks e preencha:
    URL do webhook (backend MIVI)
    https://[seu-dominio]/webhook/whatsapp
    Precisa ser HTTPS e responder ao desafio de verificação da Meta (GET com hub.challenge)
    Verify Token
    String aleatória que você define — o backend deve retornar esse token no desafio de verificação
  3. Após salvar, assine os seguintes eventos clicando em Gerenciar:
    messages · message_deliveries · message_reads · message_reactions · messaging_referrals · account_alerts
  4. O webhook agora recebe eventos de todos os clientes que conectarem via Embedded Signup. O waba_id presente em cada evento identifica o tenant.
ℹ️
A Meta envia um GET de verificação imediatamente após salvar. Seu backend deve responder com o valor de hub.challenge recebido na query string — caso contrário a configuração falha.
Etapa 3 — Uma vez

Verificação de negócio da MIVI + App Review

Sem a verificação do negócio e sem o App Review aprovado, o Embedded Signup não funciona em produção e a API fica limitada ao modo de desenvolvimento.

Verificação de negócio da MIVI Uma vez
  1. No Business Manager, acesse Configurações → Central de segurança → Verificação do negócio.
  2. Clique em Iniciar verificação, selecione Brasil e informe o CNPJ da MIVI.
  3. Envie os documentos: CNPJ ativo, contrato social, comprovante de endereço comercial em nome da MIVI.
  4. Faça a verificação do domínio do site da MIVI adicionando a meta tag fornecida no <head> do site.
⚠️
Pré-requisito crítico: o nome no Business Manager deve ser idêntico ao nome legal no CNPJ. Qualquer divergência causa rejeição automática. Prazo da Meta: 2 a 14 dias úteis.
App Review — permissões WhatsApp Uma vez
  1. No app, acesse App Review → Permissões e recursos e solicite:
    whatsapp_business_messaging · whatsapp_business_management
  2. Para cada permissão, forneça:
    — Descrição do caso de uso (ex: "Plataforma multitenant que permite que empresas enviem e recebam mensagens WhatsApp via API, com suporte a notificações transacionais e atendimento ao cliente")
    — Screencast do fluxo completo: Embedded Signup → recebimento do webhook → envio de mensagem
    — URL da política de privacidade e dos termos de serviço da MIVI
  3. Também solicite o recurso WhatsApp Business API — Advanced Access para remover o limite de mensagens por dia.
  4. Submeta para revisão. Prazo da Meta: 3 a 21 dias. Mantenha o app em modo desenvolvimento durante esse período.
✅
Após aprovação do App Review, mude o app para modo Live em Configurações → Básico → Status do app. Somente após isso o Embedded Signup funciona para clientes reais.
Etapa 4 — Uma vez

Embedded Signup — integração no frontend MIVI

O Embedded Signup é o fluxo que os clientes da MIVI vão usar para conectar suas contas WhatsApp. Já implementado no painel MIVI — esta seção documenta os pontos críticos de configuração.

Parâmetros obrigatórios no fluxo Embedded Signup MIVI configura

O botão de Embedded Signup no frontend deve iniciar o fluxo Meta com os seguintes parâmetros:

// Parâmetros do fluxo Embedded Signup
FB.login(function(response) {
  // response.authResponse.code → trocar por token de acesso
}, {
  config_id: 'SEU_CONFIG_ID',        // criado no painel do app
  response_type: 'code',
  override_default_response_type: true,
  extras: {
    sessionInfoVersion: '3',
    setup: {
      solutionID: 'SEU_SOLUTION_ID'   // ID do Tech Provider (solicitar à Meta)
    }
  }
});
ℹ️
O Solution ID é obtido ao se registrar como Tech Provider junto à Meta. Sem ele, o fluxo funciona mas sem os benefícios de parceiro (suporte prioritário, limites expandidos). Veja etapa 5.
O que o webhook recebe após o Embedded Signup do cliente Automático

Quando um cliente completa o Embedded Signup, a Meta dispara um evento para o webhook da MIVI com as credenciais do tenant:

{
  "entry": [{
    "changes": [{
      "field": "account_update",
      "value": {
        "phone_number_id": "123456789",     // ID do número do cliente
        "waba_id": "987654321",             // ID da WABA do cliente
        "event": "PARTNER_ADDED"
      }
    }]
  }]
}

Além do webhook, troque o code retornado pelo Embedded Signup por um User Access Token e depois por um System User Token de longa duração:

# 1. Trocar code por token
GET https://graph.facebook.com/v19.0/oauth/access_token
  ?client_id=APP_ID
  &client_secret=APP_SECRET
  &code=CODE_DO_EMBEDDED_SIGNUP

# 2. Gerar System User Token de longa duração via Business Manager
# Configurações do negócio → Usuários do sistema → Gerar token
# Permissões: whatsapp_business_messaging, whatsapp_business_management
🔴
Armazene por tenant: cada cliente tem seu próprio waba_id, phone_number_id e token. Nunca use as credenciais de um tenant para operar em nome de outro.
Etapa 5 — Recomendado

Registro como Tech Provider oficial da Meta

O registro como Tech Provider (parceiro de tecnologia) da Meta garante o Solution ID, suporte técnico dedicado e limites de mensagens expandidos para os clientes da MIVI.

Como se registrar como Tech Provider MIVI faz
  1. Acesse o Meta Partner Directory e clique em Become a Partner.
  2. Preencha o formulário de parceiro com os dados da MIVI — tipo de solução: Messaging.
  3. Após aprovação, a Meta fornece um Solution ID único da MIVI. Adicione esse ID no parâmetro solutionID do Embedded Signup (veja etapa 4).
  4. Com o Solution ID ativo, os clientes que conectarem via Embedded Signup da MIVI são automaticamente associados à MIVI como tech provider no sistema da Meta.
ℹ️
O registro como parceiro é opcional para funcionar tecnicamente, mas recomendado para operar em escala. Sem o Solution ID o Embedded Signup funciona — mas os clientes não ficam vinculados à MIVI no sistema da Meta.
Etapa 6 — Por cliente

O que a MIVI faz após cada cliente conectar

Quando um cliente completa o Embedded Signup, a MIVI recebe as credenciais automaticamente. Estes são os passos que o sistema (ou a equipe MIVI) executa para cada novo tenant.

Checklist pós-Embedded Signup (por cliente) MIVI executa
  1. Receber e armazenar waba_id, phone_number_id e token do webhook — associados ao tenant no banco de dados da MIVI.
  2. Gerar o System User Token de longa duração via API para o WABA do cliente — evita expiração do token de curta duração recebido no Embedded Signup.
  3. Registrar o número de telefone do cliente via API:
    POST /v19.0/{phone_number_id}/register
{
  "messaging_product": "whatsapp",
  "pin": "000000"
}
  4. Configurar o Display Name do cliente via API ou pelo WhatsApp Manager. O nome passa por aprovação da Meta (1–7 dias).
  5. Assinar o webhook para a WABA específica do cliente para garantir recebimento dos eventos:
    POST /v19.0/{waba_id}/subscribed_apps
  6. Marcar o tenant como ativo no sistema MIVI e notificar o cliente que a integração está pronta.
